# ADR-0033 — 长帖查询和显式跳页

- 状态：U09 USER_ACCEPTED，用户已批准提交；只看楼主及修复后的倒序已确认正常，其他未完成的 Live 路径继续单独记录。
- 日期：2026-10-09；基线02b32c9366d28923defc02d274d30f0e57a7c2d1。

只读PBPage使用有来源的lz/r/pn/pid，不更换已验收的iOS写请求、账号准备、上传或签名。默认全楼正序的字节和缓存键保持，模式是ThreadReadingQuery值；Store/Repository/预载请求/manifest/阅读位置共用该身份。实际倒序首屏返回current_page=1，不从Android调用端的下一页公式反推响应语义；直接使用服务端页码，严格核对目标页，后续页由服务器游标及has_more驱动，保持服务器行顺序。

用户选择查询或页时，先保存原查询的有效阅读位置，取消旧读任务；加载目标缓存或发一次目标pn请求。成功才切换显示与查询，失败保留原内容并给出可重试错误。四种模式页链/位置独立；不重新抓取所有前置页，不在生产本地filter/reversed冒充模式。明确pid导航优先于历史，验证响应包含目标后展示；没有定位结果不将另一楼标成成功。已支持pid的Repository直接取目标页，旧只支持顺序页的测试Repository保留原兼容路径。

沿用唯一VirtualizedList及现有初始恢复/视口保持。仅显式查询/跳页成功递增readingSession，给列表一个新的确定性会话身份；普通分页、刷新、图片、footer及图片查看器往返不改变它，不重建导航。旧列表回调按会话拒绝；新列表复用原一次性实际Cell定位，后续阅读位置照常记录。没有改共享虚拟列表、Pager、图片或iPad导航。

入口复用底部更多菜单，追加只看楼主、正倒序、跳页、回到首楼；页码输入用系统alert，默认重开仍全楼正序，设置中的继续上次阅读默认开启，可关闭后从顶部打开。历史项从同账号默认模式manifest读取已知楼层号，缺失不猜测，不读取全部帖子正文。新字段均可选，旧设置与阅读记录继续可读。

普通全楼正序的replySucceeded实现保持原样，只迁移函数名称以保留独立边界。新查询模式下，发送成功后的读取使用该查询的当前页刷新，不能把全楼正序getmypost结果合入只看楼主或倒序页。发送本身及默认模式的成功关闭、定向读取次数和增量回显不改变。WRITE_BASELINE原始摘要不重置，U09只读接线差异以精确可逆片段列明，原检查仍执行。

验证只覆盖相关Unit/UI、lint/build/secret-scan/diff check。无新依赖、自定义动画、手势或overlay；系统菜单及alert只在用户操作时呈现。回滚只撤U09差异，保留现有缓存和用户数据，不全仓回退。

# 人工视觉验收协议

## 为什么必须人工停顿

Unit/UI 自动化只能证明页面存在、按钮可点击和流程未崩溃，不能判断：

- 卡片是不是仍然太大；
- 信息密度是否接近 Android 原版；
- 行距、头像、等级 chip、分隔线是否自然；
- 图片网格是不是比原版更丑；
- 横滑标签、返回手势和底栏是否符合直觉。

因此每阶段必须把 Simulator 留在目标页，等用户看完再提交。

## AI 的阶段末输出格式

```text
READY_FOR_USER_VISUAL_REVIEW

阶段：
当前 commit：
未提交文件：
iPhone Simulator：
iPad Simulator（如适用）：
目标页面：
截图：
- ...
本阶段已验证：
- ...
未验证：
- ...
没有自动提交，也没有进入下一阶段。
```

## 用户检查重点

1. 与 `Docs/VisualParity/ReferenceScreenshots/Android-target` 对照。
2. 看是否仍有大圆角卡片、大面积空白、过大标题。
3. 看头像、等级、吧图和图片数量是否真实。
4. 滚动、横滑、返回、键盘、图片查看是否正常。
5. 直接列出视觉问题，不需要使用工程术语。
